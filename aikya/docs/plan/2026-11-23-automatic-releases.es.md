# Publicación automática y manual de Forge

**Objetivo:** publicar una release estable al integrar una versión nueva en main,
conservar ejecución manual y desplegar sus instaladores verificados en Pages.
**Arquitectura:** una planificación inicial de solo lectura determina preparar,
publicar, recuperar Pages u omitir una versión publicada. La publicación nueva
conserva pruebas, siete destinos nativos y revisión real; Pages solo copia la release.
**Tecnologías:** GitHub Actions, Python estándar, API GitHub y pruebas unittest.
**Especificación:** petición de releases automáticas en main y manuales; elección
explícita del usuario de VERSION y changelog de la PR, sin incremento automático.

## Restricciones y revisión

- Solo el repositorio oficial y main pueden publicar; ninguna PR publica.
- VERSION y changelog definen la versión; no se mueven tags ni reemplazan assets.
- Los errores de API no significan que falte una release. Los borradores y
  prereleases existentes se conservan y requieren revisión.
- La opción manual publish=false prepara; publish=true publica solo en main.
- Reintentar tras publicar recupera Pages desde los mismos bytes. Nunca recupera
  una versión anterior a la última estable ni reconstruye una release publicada.
- Las publicaciones nuevas siguen exigiendo evidencia real aceptada. Activar un
  evento automático no convierte el informe pendiente en una aprobación.
- No se publica ni se integra main durante esta implementación.
