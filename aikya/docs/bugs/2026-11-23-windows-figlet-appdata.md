# Windows FIGlet startup without APPDATA

## Observed failure

At 0dd3cf4132dc211091a8e95580408769ee75aee1, both Windows Pi contract jobs
(Node 22.19.0/26.13.0) returned the plain banner instead of real pyfiglet. Native
Windows x64/ARM64 builds failed their embedded-font preflight. Linux, musl and
macOS native jobs passed; Python/installers/catalog checks also passed.

The retained x64 native artifact's figlet.log showed KeyError: APPDATA during
pyfiglet 1.0.4 import. pyfiglet unconditionally uses that variable on win32, while
both the Node presentation child and native builder intentionally use bounded
minimal environments without the personal APPDATA directory.

## Correction

When Windows APPDATA is missing, the presentation adapter supplies its installed
module directory only during the library import, then removes the temporary key.
Existing APPDATA values are preserved. The helper continues using fixed bundled
slant/small fonts; no directories are created or font downloads requested. The
minimal launch/build environment and real-render native assertion are unchanged.

A fresh-process Windows-platform regression reproduced the exact KeyError before
the change and passed afterward, including restoration of the missing variable.
A project-font fixture also verifies packaged fonts continue taking precedence.
These local cases simulate the platform branch; actual Windows CI is separate.

Upstream runs: [Pi contracts](https://github.com/jlema0590/aikya-forge/actions/runs/45139529647),
