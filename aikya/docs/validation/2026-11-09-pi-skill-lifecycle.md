## Implemented boundaries

The existing three canonical skill commands support explicit project/global scope,
public commit resolution and pinned data capture, installation/selection, update,
retained rollback and reconciliation of sealed complete promotions. They are native
administration, not model tools or model consent. Network and installation have
separate native confirmations; downloaded bytes do not activate a skill.

An owned global library is inert. A project selects a concrete version and keeps an
independent immutable copy. Global updates never change that choice. Project changes
require restarting and explicitly invoking the reviewed skill; effective metadata is
checked before each provider dispatch, including old expansions still backed by
retained rollback files. Independent reviewers remain skill-free. No global project
memory or external recommendations are introduced.

One package compositor retains exact original ZIP bytes and signed prepared-file
manifests for local, captured and global sources. Public capture shares validation
and transport with the generic legacy chosen-skill entry. It requests public Git
objects/data without checkout, credentials/helpers, scripts, hooks or dependency
installation; it checks commit/tree/blob identities, complete bounded trees, regular
file modes and portable paths. The legacy adapter retains distinct data limits.
Other historical explicitly requested vendor installers are not the native path.

Native limits: 80 files, 160 discovered entries, 1 MB/file, 5 MB total, 8 KB entry,
6 KB instructions, 20 effective names and 10 retained versions per changed name.
Review, registry and provider-context limits can refuse an input earlier. Metadata
supports a bounded scalar subset, including wrapped/folded descriptions; YAML alias
or tag expansion is unsupported. Imported execution fields remain ignored data.
Data compatibility never certifies runtime behavior or external-tool availability.

Signed reservations precede package writes and promotion. Exclusive file creation,
readback and retained versions preserve previous selections. Known complete sealed
promotions can be reconciled without recopying/redownloading. Unknown/partial effects
and customized packages/archives/registries/documents are preserved and block further
mutation pending review. Legacy entries without package manifests remain readable;
update/rollback require a separately reviewed migration. No skills are uninstalled.

## Protocol sources and limits

submodule modes and truncation. [Commit resolution](https://docs.github.com/en/rest/commits/commits#get-a-commit)
provides the SHA media type; subsequent capture is pinned to the returned identity.
[Windows file naming](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)
supports the portable reserved-name/character policy. Simulated naming and junction
cases on macOS do not prove native Windows behavior.
