# Automatic release workflow validation

## Implemented behavior

The release workflow accepts main pushes and manual dispatch. VERSION and the
matching changelog section remain reviewed PR inputs, as explicitly chosen by the
user; no version is incremented automatically. A read-only plan selects publication,
manual preparation, latest stable Pages recovery or an already-published skip.
Publication retains the real-provider gate, full tests and seven-target native
assembly. Original tags/assets are never replaced. Pages retries bind to the
original published tag commit, including a manual retry after later docs changes.

The product Pages layout remains Forge's current project URL. The recommendation
is a shared Aikya portal plus separate project Pages for independently distributed
products; this change does not create portal/Mods repositories or sites.

## Observed checks

- New tests first failed because the release planner was absent. After implementation,
  the focused release/tag/gate/Pages/branding group passed all 48 cases. This includes
  eight new policy/CLI tests covering main/manual events, invalid branches/versions,
  forks, existing/conflicting tags, published/draft/partial releases, API errors,
  latest-version recovery and actual no-token preview output files.
- Native assembly and entry regressions: 16 cases completed, 13 passed and three
  PowerShell-specific cases skipped on this macOS host. No failing case.
- Source quality: three changed source/config/test files, zero errors or warnings.
- Ruby YAML parsing, extracted shell-step syntax, write-permission scoping and
  publication build dependencies passed. Python files parsed successfully.
- actionlint 1.7.12 initially rejected the new concurrency `queue` key. GitHub's
  current official workflow documentation explicitly supports `queue: max` with
  cancel-in-progress=false. Keeping it prevents default replacement of pending
  release runs. actionlint passed all remaining checks with only that exact
  unsupported-key diagnostic ignored; shellcheck/pyflakes integrations were disabled.
  This is not claimed as an unqualified actionlint pass.
- The version/release-note contract passed for the existing unpublished 0.2.0.
  Canonical index, generated record paths and diff-whitespace checks passed.

Only CI/distribution orchestration, its tests and documentation changed. The full
Python/Pi suites and seven native builds were not rerun locally for this orchestration
change; new publication still runs them in the workflow. No real GitHub release,
manual publication run, tag, main merge, Pages deployment or model call was made.
Actual hosted event scheduling and deployment remain to be observed after integration.

## Activation prerequisites

The workflow must reach main, the repository must use GitHub Actions as its Pages
source, and new publication needs current accepted real-provider evidence. The
existing provider report remains pending; this change neither fabricates observations
nor treats automatic scheduling as acceptance. Public installer availability therefore
still depends on the first successful accepted release and deployment.
