`aikya acceptance export --target /absolute/project --output
aikya/docs/validation/observation-01.json`. Choose a fresh name each time. The export
contains aggregate tokens/calls and pseudonymous provider/model IDs, never prompts,
keys or project paths. It remains provider_verified=false: local ledger data alone
cannot verify a remote provider. Runtime identity is present only for a verified
managed interpreter; an editable-source export with null identity cannot pass release.
Never edit the exported observations to fabricate missing metrics or runtime identity.

Copy only reviewed anonymized observations into the release source's validation
dossier. Complete forge-provider-acceptance.json with exact version/fingerprint,
repetitions, relative observation paths, cache_conditions, nine check outcomes and a
human review_note describing real provider provenance and comparative results. Keep
failed/unknown-usage scenario evidence separately; the three positive comparative
observations must be complete, distinct, nontruncated and current.

Run `python scripts/ci/forge_release_gate.py --version 0.2.0 --report
/absolute/source/aikya/docs/validation/forge-provider-acceptance.json`. Missing,
pending, stale, duplicate, escaped or incomplete evidence fails closed. The gate
validates documents and code identity, not the truth of a claimed external trial.
A human release decision and explicit publication request remain necessary.
No percentage of subscription quota or cost saving follows from this export alone.
