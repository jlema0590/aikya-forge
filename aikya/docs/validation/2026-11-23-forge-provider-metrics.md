# Claude and Codex provider metrics

The right sidebar now renders Context, Tokens, Usage 5h and Usage 7d separately
for anthropic (Claude) and openai-codex (Codex). Project & Git, role totals and the
Aikya local budget retain their distinct meanings.

Context uses the estimated SDK context only when explicitly bound to the active
provider. It is not duplicated into an inactive provider or inferred for the
independent review session. Tokens use measured project ledger groups, including
the existing input/output/cache counting policy. Missing/truncated/uncertain groups
retain unknown or known-minimum-plus-unknown instead of fabricated completeness.
Project-share percentages are labeled project and require complete attribution.

Account slots select exact durations, 18000/604800 seconds, from already observed
response headers. Primary/secondary names do not determine their duration. Known
zero is retained; absent/invalid/ambiguous slots remain unavailable. Source age,
failed/old observations and expired reset times keep stale labels. No endpoint
polling, credential imports, inference or compaction is added to obtain meters.

The local budget remains the configured project token/call execution guard. Its
recorded counts and limit are not a financial balance or provider account quota.
No enforcement policy or budget values changed.

## Primary references checked

OpenAI's [Codex header parser](https://github.com/openai/codex/blob/main/codex-rs/codex-api/src/rate_limits.rs)
identifies utilization and explicit window minutes; this supports selecting slots
by duration rather than primary/secondary names. Anthropic's
[API rate-limit documentation](https://platform.claude.com/docs/en/api/rate-limits)
describes request/token rate limits; these must not be substituted for subscription
5h/7d utilization. The existing recognized unified headers are treated as optional
observations, not a documented guarantee for every API authentication or plan.
