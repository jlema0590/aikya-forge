# Pi runtime boundary: first implementation slice

Status: experimental B0/B1 work on `feat/aikya-v8-pi`; not a v8 release.

The private TypeScript package `packages/aikya-pi` pins Pi 1.5.0. It creates a real
SDK session with an explicit project, in-memory settings, no discovered extensions,
skills, prompts or context files, and two active scoped read tools. It does not
execute development workflows or approve reviews. An explicit experimental
interactive launcher was added on November 8; see
[executor and terminal boundaries](2026-11-08-executor-terminal.md).

`createReadOnlySession(root, options)` exposes `/aikya-status`, `/aikya-context`,
`aikya_status` and `aikya_context`.
The command dispatches locally without prompting a model. The SDK instance has no
general file, process or shell tools. A tool-call guard also rejects unknown tools.
No model catalog refresh or credential import is performed.

Pi 1.4.0 was the research baseline. The implementation moved to 1.5.0 after
`npm audit` identified vulnerable transitive minimatch/undici versions. Contract
tests and TypeScript checks passed again after the update; the final production
dependency audit reported zero known vulnerabilities. This is not a security
certification.

Session files use the canonical project directory at `.aikya/pi/sessions/`.
Agent settings/credential storage, if used later, is separate at
`.aikya/pi/agent/`. Each directory component is checked for symlinks. Pi persists
new conversation files when it sees a user or assistant message; a custom entry
alone is buffered. Reopening the latest local conversation preserves its identity.
The terminal launcher adds a final `.aikya/pi/` exclusion while retaining existing
ignore bytes. It refuses symlinked/invalid ignore files and already tracked state,
and verifies effective rules in Git projects before initializing the agent directory.
The SDK factory alone is a trusted host API and does not manage ignore rules;
normal user launch must go through the terminal preflight. Migration remains open.

## Local service protocol

The TypeScript client launches the selected Python executable directly with
`-I -B -m aikya.services.bridge --root <canonical-project>`. Executable selection is
host configuration, never a tool argument supplied by a model. One process accepts
one JSON request on stdin and emits one JSON response on stdout. Isolated Python mode ignores project import shadows
and PYTHONPATH; the trusted interpreter must have the package installed.

Request fields are exactly `schema`, `id`, `project`, `operation`, `arguments`.
Schema is integer 1; IDs contain 1–80 ASCII letters, digits, `_` or `-`.
The project must match the server root exactly. `capabilities` and `status` take
empty arguments. `context` requires query text (at most 1,000 characters), 1–20
unique explicit safe paths and a 512–6,000 character packet budget. Requests are bounded to
16 KiB, replies to 64 KiB and execution to ten seconds by the client.
The Python service independently rejects unknown fields, duplicate JSON keys,
unsupported schemas, unsafe profile paths and oversized or malformed data.

`status` returns only `configured`, `methodology` and `project_type`. It supports
both direct and nested installed profiles; no arbitrary profile fields cross the
bridge. Missing configuration is distinguished from unreadable or corrupt data.
None of these operations writes files or imports the Claude SDK. Context retrieval
uses the existing engine with index refresh disabled. Stale indexed source is
omitted with diagnostics; missing-index fallback stays inside the supplied paths. Errors are bounded and
do not echo request contents, credentials or raw profile exceptions.

The local executor and runtime are trusted. This is not an OS sandbox or remote
attestation. Same-user races or replacement of the runtime are outside the current
boundary. Mutation and approved execution remain separate contracts to implement and verify.
Initial [RDD records](2026-11-07-rdd-contracts.md) are available through trusted host
APIs and the support CLI, without receipt-authoring tools in Pi.
